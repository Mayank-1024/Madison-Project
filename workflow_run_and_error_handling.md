# Madison Action Layer v2 — Complete Workflow Run, AI Behaviour & Error Handling

## Complete Workflow Run

**Run:** `v2-50` · 2026-10-09 · 50 events · 10 concurrent · production webhook · total wall clock 28.3 s

**Input Data:**
- 50 Madison-style variant events generated by `scale_test/make_events.py` from the 285 Assignment 3 records:
  each event = 1 ad (headline/body/CTA from the HuggingFace ad-copy dataset) + 1 campaign (company, channel, audience, conversion rate, ROI) + 1 market-context article (MarTech / Marketing Dive / HubSpot / Social Media Examiner RSS).
- Deliberately included: 15 invalid events (Popper quality-gate failures, missing headlines, invalid dates) and 1 exact repeat.

**AI Processing:**
- **Gatekeeper (no AI):** blocked 15 invalid events in 0.2 s each (HTTP 422) — no AI cost.
- **Routing Agent (Claude Haiku 4.5):** analysed 35 valid variants — scored channel fit 1–5 against each platform's limits, flagged risks with quoted evidence, and decided:
  **16 auto-approved · 18 sent to human review · 1 blocked** (placeholder text), with owner team, priority, a rewritten headline/CTA, a HubSpot task and a Slack message for each.
- **Insights Agent (Claude Haiku 4.5):** read all 50 outcomes and produced 3 patterns, 3 recommendations and a 3-item watchlist (e.g. "channel mismatch is the top risk — 16 of 50 variants; add platform format rules to the Content Agent prompt").

**Final Output:**
- **35 HubSpot tasks** created (free CRM) with title, priority, due date and the suggested fix.
- **35 Slack alerts** in `#campaign-urgent` / `#campaign-review` / `#campaign-digest` (Block Kit: decision, owner, channel fit, risks, fix, task ID).
- **1 run report** emailed via Gmail + posted as a Slack digest + saved as `outputs/madison_run_report.html` / `.pdf`.
- **Decision log** appended to Google Sheet "Madison Action Log" (exported: `outputs/action_log_v2-50.csv`) and stored in the n8n Data Table `madison_action_log`.
- AI cost for the whole run: **$0.1556** ($0.0044 per routed variant).

## What the AI decides and produces

| Agent | Decides | Produces | Constrained by |
|---|---|---|---|
| Routing Agent (per variant) | `decision` (auto_approve / needs_review / block), `priority` (urgent/high/normal/low), `owner_team`, `slack_channel`, `confidence` | channel-fit score + note, risk flags (type, severity, exact evidence), rationale, suggested fix, HubSpot task title/body/due days, Slack message | Strict JSON schema with enums (`output_config.format`), severity rules in the system prompt, untrusted-data rule (ignores instructions inside ad copy) |
| Insights Agent (per batch) | what matters this week | headline, 3 patterns, 3 recommendations, watchlist | JSON schema; told to use only the batch numbers provided |

**What it learned from testing (prompt v1 → v2):** v1 blocked 85% of variants because the test data paired fashion ads with unrelated news and random campaign types; Claude was technically right but unhelpful. v2 recalibrated severity (placeholders and false factual claims = high; marketing adjectives = low) and treats news as optional market context. Result: a realistic 32% / 36% / 2% (+30% Gatekeeper) mix, faster (p50 6.4 s vs 8.9 s) and cheaper ($0.0044 vs $0.0050). The Insights Agent's recommendations are the feedback loop back into Madison's Content Agent.

## Error Handling

**What could go wrong:**
- API rate limit exceeded (Anthropic 429) or timeout / 5xx from Claude
- AI returns malformed, truncated or refused output, or values outside the allowed set
- Input data missing required fields, invalid dates, or failing Madison's Popper quality gate
- The same variant sent twice
- HubSpot / Slack / Gmail / Google Sheets unavailable or rejecting a request
- Network issues between n8n and any service
- An unexpected crash anywhere in the workflow

**How we handle it:**
- **Retry:** every external call (Claude, HubSpot, Slack, Gmail, Sheets) retries 3× with a 5 s wait, then **continues on error** instead of stopping.
- **Validate before acting:** `Validate AI Decision` checks for API errors, `stop_reason` refusal / max_tokens, JSON parse failure, invalid enum values and missing text. Any failure → **rule-based fallback router** (regex risk checks + team by channel) routes the variant to `#campaign-review` with "⚠️ AI router unavailable", so nothing is lost.
- **Reject bad input early:** the Gatekeeper blocks invalid payloads with HTTP 422 and logs the reason (no AI cost).
- **Idempotency:** `brief_id:variant_id` is checked against the action log; repeats return `duplicate` with no new task or alert.
- **Log and continue:** if HubSpot or Slack fails, the outcome is logged as `partial_failure` with the error text and the workflow answers Madison anyway.
- **Notify:** n8n **Error Workflow** (`workflow_v2_error_handler.json`) posts any unhandled crash to Slack `#campaign-urgent` with the failing node and error message.
- **Protect the entry point:** the webhook requires a Header Auth key; no secrets are stored in the exported JSON.

**Evidence:**
- 834 real requests across all load tests: 0 HTTP errors, 0 timeouts, 0 crashes; 140+ invalid events correctly rejected (422); duplicate re-send returned `duplicate` in 0.19 s (`screenshots/11.png`).
- **Live AI-failure test (2026-10-09, run `fallback-1`):** the model ID was deliberately set to an invalid value (`claude-haiku-x`). Claude's API returned "The resource you are requesting could not be found"; the HTTP node retried 3× and continued; `Validate AI Decision` set `ai_ok: false, ai_problem: api_error…`; the **Rule-based Fallback Router** routed the variant to `#campaign-review` with "⚠️ AI router unavailable … needs a manual check", created a HubSpot task, logged `ai_status = fallback`, and answered Madison with HTTP 200 in 11.8 s at $0 AI cost — no crash, no lost event (`screenshots/17.png`, `18.png`, `19.png`, `scale_test/results/fallback-1.json`).
- The other AI-failure paths (429, malformed JSON, invalid enum, HubSpot outage) were exercised with simulated responses during the build.
- Known gap: two identical events arriving at the same moment are both processed (non-atomic check-then-insert) — fix documented in `scale_test_results.md` (unique constraint / Redis `SETNX`).
